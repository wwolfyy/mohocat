# R-0437 — 193 relative links across the docs do not resolve, most of them in docs/handoff/archive/

> **bug · done** · 2026-08-09
> Measured while doing `R-0428`, which needed a before/after baseline to prove the file move broke
> nothing. The baseline turned out to be the finding.

---

**A repo-wide check of every relative markdown link in every tracked `.md` file — 1,046 links —
finds 193 that point at nothing.**

| Area                     | Broken |
| ------------------------ | -----: |
| `docs/handoff/`          |    102 |
| `docs/planning/`         |     37 |
| `work_tracking/records/` |     29 |
| `docs/manuals/`          |     12 |
| `docs/archive/`          |      7 |
| `scripts/migration/`     |      3 |
| `docs/design/`           |      2 |
| `docs/codebase/`         |      1 |

**Two distinct causes, and they want different fixes.**

🔑 **The 102 in `docs/handoff/` are a depth error from an old move.** Those files used to live at
`docs/handoff/<name>.md` and linked to siblings as `../planning/…`. They were relocated into
`docs/handoff/archive/` and the links went with them unchanged, so each now resolves one directory
too shallow — `docs/handoff/planning/…`, which has never existed. The same shape accounts for most
of `docs/planning/`. **Mechanically fixable**, because the intended target is unambiguous.

⚠️ **The 29 in `work_tracking/records/` are different and are not a move at all.** Record prose is
lifted **verbatim** from its source file and `.prettierignore` keeps it that way, so that
`source_ref` stays checkable against `git show`. A link that was correct in
`docs/planning/PROJECT_PLAN.md` is wrong when the same text sits in `work_tracking/records/`, and
**rewriting it would break the verbatim guarantee** the import rests on. 📌 The real question is
whether a record's body is a quotation or a document — it is currently both, and this is where
that tension shows. Worth deciding before any bulk fix.

**Not urgent, and deliberately not folded into `R-0428`.** Every one of these was already broken
before that change; a move that repairs unrelated rot is a move whose own diff cannot be read.
`R-0428`'s rewriter skips any link that does not currently resolve, precisely so a
differently-broken path does not bury the original.

📌 **A link check would be cheap to make permanent**, and the shape is already proven —
`work_tracking/scripts/size-check.js` plus its CI step is the same pattern, and the throwaway
checker used here is about 40 lines. ⚠️ It cannot be turned on as a hard gate until the 193 are
dealt with, so the order is: decide the records question, fix, then gate. Turning it on first
would mean a permanently red job, which teaches everyone to ignore it.

⚠️ **It also has a false-positive mode that has to be handled first, found by running it.**
Markdown link *syntax* quoted inside prose is indistinguishable from a link. `R-0428` explains a
cosmetic-churn problem by writing `](sibling.md)` and `](./sibling.md)` as examples, and the
checker reports both as broken — correctly by its own rules, wrongly by intent. Any real gate
needs to skip fenced blocks and inline code spans, which the throwaway version does not.

---

## Resolution (2026-08-09)

**Owner's call: repair everything outside `records/`, leave `records/` alone, then gate.** Done in
that order, which is the order the record argued for.

**52 links repaired**, across 24 files in `docs/planning/`, `docs/manuals/`, `docs/codebase/`,
`docs/design/`, `docs/handoff/testing/` and `scripts/migration/`. 🔑 **Every one was a pure
depth error, and that is what made a bulk repair safe** — the target existed the whole time, at a
path the link no longer described. Three moves account for nearly all of them: plans sorted into
`planning/pending/` and `planning/completed/`, hand-offs relocated into `docs/handoff/archive/`,
and `PROJECT_PLAN.md` moved to `work_tracking/` by `R-0428`.

📌 **Repaired by resolving each target's longest matching path suffix, not its basename.** Basename
alone is ambiguous exactly where it matters: `../manuals/deployment/README.md` and
`../manuals/admin-manual/README.md` both reduce to `README.md`, of which the repo tracks eight.
Matching the longest suffix picks the right one and refuses to guess when nothing is unique.

⚠️ **The gate exempts three trees, and an exemption is not a fix.**

| Tree                     | Broken | Why it is exempt                                          |
| ------------------------ | -----: | --------------------------------------------------------- |
| `docs/handoff/archive/`  |     96 | frozen history; repointing edits the record of the day    |
| `docs/archive/`          |      6 | frozen history                                            |
| `work_tracking/records/` |     26 | prose is verbatim, so a rewrite breaks the `source_ref`   |

🔑 **The cost of the third exemption is worth naming, because nothing else will say it:** a
genuinely broken link in a **new** record is not caught either. That is the price of the verbatim
guarantee, and the reason the exemption sits in a commented block in `link-check.js` rather than in
a quiet skip-list. 📌 The underlying question — whether a record body is a quotation or a document
— is still open; it is now merely no longer blocking anything.

**The gate is `work_tracking/scripts/link-check.js`**, wired into the `work-tracking` CI job as its
fourth step, alongside the store tests, `build --check` and `size-check`. `link.test.js` (21
assertions) covers it, and the load-bearing ones are the false-positive cases above: a link inside
a fence or an inline span must not be reported, or the gate fails on this repo's own documentation.
📌 **It also proves the gate exits 1**, against a throwaway git repo reached through
`WORK_TRACKING_LINK_ROOT` — a scratch file inside this repo is untracked, `git ls-files` never
returns it, and the failure path would otherwise never run. That is the `size.test.js` lesson:
a check that always returns 0 passes every other test in the suite. An anchor is checked **as far as the file** — `SCHEMA.md#no-such-heading` passes,
because headings are renamed far more often than files move, and a fragment check would be a
different and much noisier gate.
