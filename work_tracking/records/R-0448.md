# R-0448 — Make emoji markers scarce in the four living documents, and gate the density

> **task · open** · 2026-08-13
> Owner decision, 2026-08-13, taken at the end of the writing-quality discussion that produced
> `R-0447`. Execution deliberately deferred to a fresh session.

---

## The decision

Apply marker scarcity to the four documents every session reads — `AGENTS.md`, `WORKFLOW.md`,
`SCHEMA.md` and `HANDOFF.md` — and enforce it with a gate rather than a written convention.

Records are explicitly out of scope. There are more than 440 of them, they are read on demand
rather than every session, and the prose of every imported one is verbatim from its source with
`source_ref` pinning it to a commit. Rewriting those would break the audit trail the migration
rests on. New records should simply be written lighter as a habit.

## What was measured, on 2026-08-13

One marker per N lines, counting the set the repository actually uses
(`⚠️ 🔑 📌 ✅ 🔴 🎯 🕐 🔁 🔍 📝 📏 📄 🎉 ⏭️ ❌ 🔄`):

| Document                      | Lines | Markers | One per   |
| ----------------------------- | ----: | ------: | --------- |
| `HANDOFF.md`                  |   197 |      39 | 5.1 lines |
| restructure design doc        |   477 |      71 | 6.7       |
| `WORKFLOW.md`                 |   236 |      26 | 9.1       |
| `AGENTS.md`                   |   321 |      31 | 10.4      |
| `SCHEMA.md`                   |   312 |      18 | 17.3      |

Bold spans run between 0.19 and 0.43 per line in every file measured, old and new alike.

Two things follow from this that were not obvious before measuring. The density is the
repository's existing convention rather than something the 2026-08-10 documents introduced, and
`HANDOFF.md` is the densest file in the repository while also being the one `AGENTS.md` instructs
every session to read first.

## Why it is a problem

A signalling system works by being scarce. The repository assigns these markers real meanings: the
warning triangle means watch out, the key means this is the load-bearing point, the pin means this
is an aside. At one marker every five to seven lines, close to every paragraph carries one, so the
markers no longer tell a reader which paragraph to slow down for.

There is a second effect that matters more, and it is why this is a writing problem rather than a
formatting preference. Writing "key: X" in bold asserts that X is important. Writing "X matters
because Y" earns it. Reaching for a marker is one of the ways the "because" gets dropped, so the
density is a symptom of the same habit `R-0447` corrected in seven specific places.

Bold has a third problem of its own. It is doing three unrelated jobs in one visual channel:
ordinary emphasis, marking key terms such as `row` and `rev`, and acting as a headline label at the
start of a paragraph. A reader who scans the bold gets a broken telegram rather than a summary.

## Why a gate rather than a convention

`R-0424` is the precedent, and its lesson was that the archive mechanism for `HANDOFF.md` was never
missing — it simply stopped being applied, until the size budget made it a CI failure. A density
convention would decay the same way, and it would decay invisibly, because nothing about a
too-marked document fails.

## Notes for whoever picks this up

The natural home is `size-check.js`, which already reads a per-document policy and already measures
two properties per file. A third measurement fits its existing shape, and `size-policy.json` already
has a `remedy` string per document that the failure prints.

Two questions need answering first, and neither has been settled:

- What ratio counts as scarce? `SCHEMA.md` at one per 17 lines reads comfortably and is a plausible
  target. Setting the ceiling at the current worst value would gate nothing.
- Does the ceiling count distinct markers or total markers? A paragraph opening with a warning
  triangle and containing two pins is a different problem from three paragraphs each carrying one.

Ratchet the budgets the way `size-policy.json` already does, which means setting each ceiling just
below the document's value after the cleanup, so that adding markers back requires editing the
policy in a visible diff.
