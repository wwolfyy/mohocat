**One file is half of the `project` total.** `phase2-leaflet-status.md` is 18,644 bytes in 52

## Why this is worth doing now rather than at any earlier point

The memory guidance says not to save what the repository already records. When most of these
`project` memories were written, that instruction had little bite, because the repository had no
single place holding project state. **The work registry changed that on 2026-08-08/09.** So these
files predate the thing that now covers them, and the overlap is a consequence of sequence rather
than of anyone ignoring the rule.

There is also a correctness reason, not only a size one. `phase2-leaflet-status.md`'s own front
matter describes Phase 2 as "in progress; where to resume", while the `MEMORY.md` index line for it
says Phase 2 is complete. At least one of the two is stale. A registry record carries revisions and a
status field; a memory file carries neither, so it has no way to record that it has been superseded.

## The work

Go through the nine `type: project` memories and decide, per file, between three outcomes rather
than two:

- **Delete** — a registry record already holds it, and the record is authoritative.
- **Move** — the content is durable explanation rather than state, so it belongs in
  `docs/codebase/` or in a record, not in memory. Several look like this: the portal and
  native-image traps in `modal-design-system.md`, and the fail-loud guards in `asset-pipeline.md`,
  explain how the system works rather than where the work stands.
- **Keep** — nothing else holds it and it is genuinely about working on this project.

Start with `phase2-leaflet-status.md`, which is both the largest and the one with a known internal
contradiction.

⚠️ **Leave the seven `feedback` memories alone.** Guidance about how to work is not something the
registry tracks, and at 16.8 KB total they are proportionate. `plain-language-explanations.md` and
`emphasis-marker-discipline.md` were both written or extended on 12–13 August and are current.

## Two things to know before starting

The memory files are **not in this repository and not versioned with it**, so this record cannot
name them in its `files` field in any way a reader can check out, and a future human reader of the
registry cannot inspect them at all. That asymmetry is the reason to be conservative: deleting a
memory is unrecoverable in a way that deleting a tracked file is not.

📌 **`MEMORY.md` is the only part with a per-session cost.** It is loaded into context every
session; the individual files are read only when something makes them relevant. At 18 lines and 3 KB
the index is cheap, so the 58 KB total is not a context problem and this audit is about staleness
and duplication rather than about size.
