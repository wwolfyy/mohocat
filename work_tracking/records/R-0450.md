# R-0450 — Make the pre-commit hook verify rather than repair, and format on save instead

> **task · open** · 2026-08-13
> Owner-raised on 2026-08-13, after the `704020d` commit showed the hook rewriting staged content
> after the gates had already been run against it.

---

## The defect

`.husky/pre-commit` runs three things in order: TruffleHog, then `npx lint-staged`, then
`npm run typecheck`. The middle step **mutates**. `.lintstagedrc.js` runs `next lint --fix` on
JavaScript and TypeScript and `prettier --write` on both that glob and
`**/*.{css,scss,md,html}`, and lint-staged then re-stages whatever those commands changed — its
own output says "Applying modifications from tasks".

So the bytes verified before a commit are not necessarily the bytes committed. On `704020d` the
hook reformatted across 183 markdown files and 6 JavaScript files **after** the four work-tracking
gates had been run. Nothing broke, but only because Prettier had already been run by hand on
everything touched. That is luck rather than a property of the setup.

The realistic failure this exposes: Prettier pads table columns to the width of the widest cell,
and `size-check.js` gates on the longest line in a governed document. A hook-applied reformat can
therefore push a document over its column budget after the size gate has passed, producing a green
commit and a red CI job.

## The four changes

- [ ] **`.lintstagedrc.js`: `prettier --write` becomes `prettier --check`.** Prettier exits
      non-zero on an unformatted file, so the commit is refused instead of silently rewritten.
- [ ] **`package.json`: add `format` (`prettier --write .`) and `format:check`
      (`prettier --check .`).** Neither exists today. A refused commit needs a one-command remedy,
      or the friction pushes people to `--no-verify`.
- [ ] **Add `.vscode/settings.json` and `.vscode/extensions.json`.** Format on save with Prettier
      as the default formatter, plus `editor.codeActionsOnSave` with `source.fixAll.eslint`, and
      recommend both extensions. There is no `.vscode/` directory today and it is not gitignored,
      so committing it shares the settings.
- [ ] **Drop `--fix` from the `next lint` invocation.** See below — it is currently a no-op.

These land together or not at all. Switching to `--check` without the `format` script and the
editor settings is hostile: it starts refusing commits without giving anyone the remedy.

## Why dropping `--fix` costs nothing

Measured on 2026-08-13, `npm run lint` reports nine violations and **every one is a warning, and
none is auto-fixable**. Eight are `react-hooks/exhaustive-deps`, which deliberately ships no
automatic fix because adding a missing dependency changes when an effect re-runs. The ninth is
`no-img-element`, which cannot be fixed mechanically because replacing a bare `<img>` with
`next/image` requires knowing the dimensions and the loader.

So `--fix` is repairing zero violations. Removing it changes nothing measurable today, and it only
begins to matter if a rule with a real fixer is added later, such as import ordering.

## What this does not fix

Format-on-save covers a person using VS Code. It does nothing for an agent editing files through
tooling, because no editor is saving them. **The refusal is what covers that case**, which is most
of the value: it converts "I remembered to run Prettier" into a requirement.

📌 After this, the whole hook becomes verify-only — TruffleHog only scans and `tsc --noEmit` only
checks — so the type check at the end will be validating exactly what is about to be committed,
which today it is not.

⚠️ **The work-tracking gates still do not run in the hook at all**, only in CI. That is a separate
gap, deliberately not folded in here, and it is not yet recorded anywhere.
