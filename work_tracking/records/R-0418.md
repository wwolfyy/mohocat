# R-0418 — The work-tracking CI job is independent of the app's jobs

> **decision · done · adopted** · 2026-08-09
> Migrated from `work_tracking/MIGRATION_JOB.md` — "Decisions made during execution" and the
> Phase 1 session entry (`work_tracking/MIGRATION_JOB.md#D-independent-ci-job@44e08fe`).

---

**The `work-tracking` job in `.github/workflows/ci.yml` takes no `needs:` and runs no `npm ci`.**
It checks two things: that the store loads clean, and that `registry.md` equals
`build(registry.ndjson)`.

**Two reasons it stands alone:**

1. **It needs a different Node.** The tooling has zero dependencies because `node:sqlite` is
   built in — but only from Node 24, and the app's jobs run Node 20.
2. **It must report when the app build is red.** A gate chained behind a failing build says
   nothing, and the store's integrity has no relationship to whether the app compiles.

⚠️ **The gate and the formatter will fight over generated files, and the gate has to win.** On its
first run the pre-commit hook's Prettier reformatted the generated `registry.md`, so it no longer
equalled `build(registry.ndjson)` and `--check` failed immediately after the commit that added
it. Fixed by adding it to `.prettierignore` — formatting a generated file is `build.js`'s job.
`work_tracking/records/` is ignored for a related reason: reflowing migrated prose would mean the
stored text no longer matches what `git show <pin>` returns, which is the audit trail.

📌 `--check` writes nothing, including no `registry.db`. A gate that writes a file is no longer
only checking, and `workflow.test.js` pins that.
