# R-0452 — Decide whether ESLint warnings should fail the build, and answer the nine that exist

> **task · open** · 2026-08-13
> Kept separate from `R-0450` and `R-0451` at the owner's instruction, because unlike those two it
> fails the commit on the day it lands.

---

## The situation

Warnings do not fail `next lint`. Nine violations have therefore been sitting in the codebase while
the pre-commit hook reports them and passes. Measured 2026-08-13:

| Rule                          | Count | Where                                                                               |
| ----------------------------- | ----: | ----------------------------------------------------------------------------------- |
| `react-hooks/exhaustive-deps` |     8 | `VideoAlbum`, `AboutContentEditor`, `RoleManagement`, `usePermissions` (×4), and one more |
| `@next/next/no-img-element`   |     1 | `src/components/ui/Lightbox.tsx:128`                                                |

Adding `--max-warnings=0` makes them fatal. That is the decision, and it cannot be taken without
first answering the nine, which is why this is one record rather than a flag change.

## The nine are not one problem

**The eight hook-dependency warnings are real and each needs a judgement.** `exhaustive-deps` ships
no automatic fix precisely because the two available answers differ in behaviour: adding the missing
dependency makes the effect re-run when it changes, and that is sometimes the bug fix and sometimes
a new infinite loop. Four of them are in `usePermissions.ts`, which resolves a user's effective
permissions, so getting one wrong has an authorization consequence rather than a cosmetic one.

⚠️ **The `<img>` in `Lightbox.tsx` looks deliberate rather than accidental.** There is a known
requirement in this project that the lightbox uses a native `<img>` rather than `next/image`. If
that holds, the correct outcome is **not** to fix it but to add an inline
`// eslint-disable-next-line @next/next/no-img-element` carrying the reason, so the decision is
recorded at the site instead of reappearing as an unanswered warning forever. 📌 **Verify the
requirement against the component before assuming it** — this note comes from a memory written in an
earlier session, and a memory is a point-in-time observation rather than current fact.

## Order

Do this **after** `R-0451`, not before or alongside. `R-0451` may change which rules run at all,
since the dormant flat config adds `next/typescript` and stops suppressing
`react/no-unescaped-entities`. Making warnings fatal first would mean answering a set of warnings
that is about to change, and doing both at once makes it impossible to attribute a failure.

## Cheapest first step

Run `npx next lint --max-warnings=0` without committing anything. It costs nothing, and it shows
exactly what the gate would reject before anyone commits to fixing the list.
