# R-0443 — Which rules belong in AGENTS.md: the ones that fail silently, and each explanation names its rule

> **decision · done · adopted** · 2026-08-10
> Owner-raised: `R-0441` said `AGENTS.md` states rules and `WORKFLOW.md` explains them, but did not
> say **which** rules — so some sat in both files and some in neither.

---

**Two gaps, both real.**

⚠️ **`R-0441` gave a rule about placement without a test for it.** "State the rule in `AGENTS.md`"
is unusable unless you know what counts as a rule that belongs there. The result was visibly
inconsistent: `--out`, `work.json` and never-grep appeared in **both** files, while **"check out
everything you intend to reference"** and **"do not hand-edit the conflicted lines"** appeared only
in `WORKFLOW.md`. 🔑 **And the loop itself was never stated as a rule at all** — `AGENTS.md` showed
the commands in a bash block, which reads as a convenience, not as _the only way to write to the
store_.

⚠️ **Nothing tied an explanation to the rule it explained.** `WORKFLOW.md` §2 said "the rules are in
`AGENTS.md` §A" once, at the top, so no individual section could be checked against its rule.

## The test: what happens when you do not know the rule

| If you do not know it                                          | Home                                | Example                                     |
| -------------------------------------------------------------- | ----------------------------------- | ------------------------------------------- |
| **The tooling refuses**, and the message says what to do        | `WORKFLOW.md`, beside the mechanism | check-in rejecting an un-checked-out parent |
| **You cannot reach it** without already reading that section    | `WORKFLOW.md`, beside the mechanism | merge-conflict recovery                     |
| 🔴 **Nothing stops you and the result looks fine**              | **`AGENTS.md` §A**                  | hand-editing the store; grep                |

🔑 **Only the third tier earns a place in the file every session loads**, and that is exactly what
makes it a short list rather than a manual. It also explains the two that were already there: a
hand-edited row and a record checked in early both produce a store that loads clean, passes every
gate, and is wrong.

📌 **This retires the open question in `R-0442` about never-grep.** Grep is **tier 3** — it does not
error, it returns a plausible number that happens to be wrong in both directions — so the rule
belongs in `AGENTS.md`. What moves out is only the *demonstration*; `AGENTS.md` carries the rule
plus the one clause that makes it land ("append-only and JSON-escaped"), and `WORKFLOW.md` §5 keeps
the two commands that prove it.

## The rules, named

> ⏭️ **There are four, not three — see `R-0444`.** This record named R1, R2 and R3, which was the
> full set on 2026-08-10. `R-0444` then found that the same-change rule had been sitting in
> `AGENTS.md` §A unnumbered, and promoted it to **R4**. Everything below still holds; the count does
> not.

Naming them **R1 / R2 / R3** is what makes the pairing checkable. Each `WORKFLOW.md` section now
opens with **"Explains R_n_"** and restates the rule in **one line**.

⚠️ **A one-line reference is not the restatement `R-0441` banned.** The banned thing is a second
*authoring* — a paragraph that grows its own wording and drifts. A one-liner that names the rule is
a **cross-check**: if it and `AGENTS.md` §A ever disagree, someone edited one alone, and that is now
visible instead of silent. `WORKFLOW.md` §2 says so explicitly.

## What changed

- **`AGENTS.md` §A** — R1 (the loop is the only write path, absorbing never-hand-edit as its
  negative form), R2 (finish the work, then check in), R3 (never grep; pass `--out`). Plus a line
  saying **the list is deliberately not every rule**, and why.
- **`AGENTS.md`'s "prior sighting of a bug" bullet** no longer restates never-grep — it points at
  R3. That was `AGENTS.md` duplicating **itself**, which `R-0442` had not spotted.
- **`WORKFLOW.md`** — §2.1, §2.2, §4 and §5 each open with the rule they explain; §4 was reworded
  from instruction to explanation; the two `WORKFLOW.md`-only rules are now **labelled as such**,
  so they read as placed rather than forgotten.

📌 **The command block in `AGENTS.md` stays.** It is the annotated starter for a first session;
`WORKFLOW.md` §1 is the complete reference including `--check`, `db.js` and the test runner. Same
text, different jobs — and R1 now says out loud what the block previously only implied.
