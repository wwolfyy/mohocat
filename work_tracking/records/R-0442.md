# R-0442 — Three statements still live in both AGENTS.md and WORKFLOW.md, and they predate the split

> **task · open** · 2026-08-10
> Found while fixing the two duplications `R-0441` had just created — these three were already
> there and were inherited by the split rather than caused by it.

---

**`R-0441` established the layering: `AGENTS.md` states the rule, `WORKFLOW.md` explains why, and
neither restates the other.** Applying it turned up three statements that break it and were not
written by that change.

| Statement                                        | `AGENTS.md` | `WORKFLOW.md` | Verdict                    |
| ------------------------------------------------ | ----------- | ------------- | -------------------------- |
| Never `grep` the store, with the escaping example | 303–307     | §5            | ⚠️ **judgement call**      |
| `work.json` is gitignored, never commit it        | 109         | §4            | straightforward — trim one |
| The check-out → check-in → build commands         | 54–61       | §1            | probably fine as it stands |

⚠️ **Never-grep is the one that is genuinely arguable, and it should not be trimmed reflexively.**
The rule is _"do not grep `registry.ndjson`"_, but the rule alone does not persuade anyone — the
reason it lands is the demonstration that `"Post not found."` is stored as `\"Post not found.\"`
and that a plain grep therefore returns **0**. 🔑 **For this rule the evidence _is_ the statement**:
someone who reads only the imperative will assume they are being told to be tidy and will grep
anyway, because grep appears to work. That is a real argument for keeping the example in the file
everyone loads, and it is the one case where the `R-0441` layering may simply be wrong.

📌 **`work.json` is the easy one.** `AGENTS.md` says it is gitignored and must not be committed;
`WORKFLOW.md` §4 says the same and adds the reason (it was committed once, a merge filled it with
conflict markers, and it is the recovery file). That is exactly rule-here / evidence-there, so
`AGENTS.md`'s copy should shed the explanation it currently duplicates.

📌 **The command block is probably not a duplication at all.** `AGENTS.md` shows the two or three
commands you need to start, annotated for a first session; `WORKFLOW.md` §1 is the complete
reference including `--check`, `db.js` and the test runner. Different jobs, overlapping text. 🔑
**Worth deciding rather than assuming** — if it is a duplication, it is the most-copied text in the
repo's tooling docs and will drift first.

**Not urgent.** Nothing here is wrong today; all three copies currently agree. The cost is the
ordinary cost of a copy — the day one is edited, and `R-0440` showed that day can arrive within
twenty-four hours.

⚠️ **A gate cannot catch this.** `link-check.js` verifies that links resolve, not that prose is
stated once, and there is no cheap mechanical test for "these two paragraphs say the same thing."
This is a review-time judgement, which is why it is a record rather than a CI step.

## Resolved by `R-0443` (2026-08-10)

All three are settled, and the judgement call went the way this record flagged as possible:

- ✅ **Never-grep stays in `AGENTS.md`** — as **R3**. `R-0443`'s test makes it **tier 3**: grep does
  not error, it returns a plausible wrong number. What moved out is only the demonstration.
  `AGENTS.md` keeps the rule plus the clause that makes it land; `WORKFLOW.md` §5 keeps the two
  commands that prove it. 🔑 **So "the evidence _is_ the statement" was half right** — the *reason*
  is, the *worked example* is not.
- ✅ **`work.json`** — `AGENTS.md` instructs, `WORKFLOW.md` §4 was reworded to explain only.
- ✅ **The command block is not a duplication**, as suspected: an annotated starter versus the
  complete reference. It stays, and **R1** now states out loud what it previously only implied —
  that the loop is the only write path.

📌 **One thing this record missed.** `AGENTS.md` was duplicating **itself**: the "prior sighting of
a bug" bullet restated never-grep, escaping example and all, a couple of hundred lines below §A.
This audit compared the two files against each other and never compared a file with itself.
