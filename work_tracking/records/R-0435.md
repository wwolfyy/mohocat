**Root cause.** The source markdown contains **continuation lines that start at column 0** inside
an indented list item — `` (`uploadDate: new `` ends a line and `` Date()`), reordering… `` begins
the next one with no indent. By the markdown spec the list item **ends there**, so an importer that
reads items structurally takes everything before the unindented line and nothing after it. The
import was faithful to the parse; the parse was faithful to text that was already malformed.
`.prettierrc` does not reflow prose (`proseWrap` defaults to `preserve`), so the bad indentation
survived every format run that might otherwise have repaired it.

🔑 **Two defects, not one.** The record lost its tail **and** the tail stayed behind in
`PROJECT_PLAN.md` as a free-standing paragraph that reads as broken prose. Four of those orphans
are still in the file, immediately after a roll-up pointer:

- after §7's pointer — `` > Date()`), reordering the **public** 영상첩… `` (`R-0186`'s tail)
- after §7a's pointer — `` > `points-static-data.json`/`feeding-spots-static-data.json`… ``
  (`R-0209`'s)
- after §10a's pointer — `` > .youtubePlaylistId`per mountain… `` (`R-0240`'s)
- after §10n's pointer — `` > uploadingAsSelf()`. 📌 **`cat_videos` deliberately gains nothing** ``
  (`R-0291`'s)

The six remaining tails are **not** in the working tree at all — their source files are stubs now.
They are recoverable only from the pinned commits, which is exactly what `source_ref` is for.

⚠️ **This is the same class as `R-0429` and it escaped for the same reason.** Row counts, the
determinism test and `build.js --check` all pass on a truncated record, because a truncated record
is still a **valid** record. `R-0429`'s repair added a real-store assertion for **empty** bodies;
nothing asserts a body is **complete**.

🔑 **The six from `PROJECT_PLAN.md` needed no judgment at all.** Each body was verified to be a
**clean prefix** of its source item before anything was written, so the repair is the item read
whole — not a reconstruction. `R-0240` and `R-0291` had been reduced to a single opening line.

⚠️ **The four from `HANDOFF.md` did need judgment, because that import cut on _line numbers_, not
on sentence or topic boundaries.** They were sliced out of one long session-log bullet by range —
`L2932–2941`, `L2942–2943` — so two of them were broken at **both** ends: `R-0397` opened with
`mapping.`, the tail of the sentence that belongs to `R-0396`, and `R-0403` opened with
`recorded in the plan doc.`, the tail of a sentence about something else entirely. Each was
re-cut to the sentence boundary that keeps its own topic whole and nothing else's.

📌 **One judgment call worth naming.** `R-0403`'s slice also carried three incidental finds from
2026-07-19 — a hydration-race flake in the contact-submit spec, `test:e2e` clobbering `public/`
images with emulator fixtures, and the `openjdk` PATH. They are kept **verbatim** in the record
rather than dropped, because only the third is written down anywhere else (`HANDOFF.md`'s e2e

deliberate non-action rather than an oversight.

**The four orphaned tails are gone from `PROJECT_PLAN.md`** — §7, §7a, §10a and §10n now end at
their roll-up pointer. §7 in particular had **19 lines** of broken prose after its pointer.

**The gate that would have caught it**, in `work_tracking/tests/store.test.js`:

- `no record file ends mid-sentence` — the last prose line must end on terminal punctuation.
- `no record file leaves a code span unclosed` — an odd backtick count, counted only after fenced
  blocks and double-backtick spans are stripped, longest delimiter first. Without that stripping a
  record that legitimately quotes a backtick inside a double-tick span reads as unbalanced —
  which this record did, and the check caught it while it was being written.

⚠️ **Both were proven to have teeth, not just to pass:** re-truncating `R-0186` at its original
cut point fails both, and restoring it turns both green. Between them they catch all ten —
neither alone does. Nine fail the sentence rule; `R-0214` ended on `` (`assignedBy: ``, which is
_terminal punctuation_ and only the backtick rule sees.
