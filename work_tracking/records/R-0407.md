# R-0407 — The owner archives superseded artifacts to `docs/archive/` by hand — the migration does not relocate files

**Owner's call, 2026-08-08.** The migration's job is to stop a file being the live source of any
open item. Moving the emptied file somewhere else is a separate act, and the owner does it by
hand afterwards.

**Why the two are separated:** they fail differently. Cutting an origin in the same commit that
adds its rows is a correctness rule — a half-migrated backlog is worse than either end state — and
it is enforced by the importers. Relocating a file is a tidying preference with no correctness
content, and folding it into the migration would have meant every import commit also churned
paths, breaking links for reasons unrelated to the data.

⚠️ **The archive move is not free, and it is not scheduled.** The 20 companion-document records
from `R-0406` carry `detail_ref`s pointing at `docs/planning/**`. Archiving those folders breaks
all 20 at once. **`R-0427` holds that work, deferred on exactly this condition** — it starts when
the move does, and it must land in the same change.
