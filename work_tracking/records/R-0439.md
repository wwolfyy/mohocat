# R-0439 — The session-close hand-off procedure is now a skill, .claude/skills/handoff/

> **change · done** · 2026-08-09
> Owner's request: stop asking for the hand-off to be updated by hand at the end of every session.

---

**What existed already, and why it was not enough.** Six places say something about
`work_tracking/HANDOFF.md`, and between them they are a reasonable specification of **what the file
should contain**:

| Where                            | What it establishes                                                             |
| -------------------------------- | ------------------------------------------------------------------------------- |
| `HANDOFF.md` "How this file works now" | Contents, and that a finished chunk changes **the record, not this file**  |
| `HANDOFF.md` size note           | 250-line CI budget; near it, delete history rather than raise the number         |
| `size-policy.json`               | The remedy when it trips: archive to `docs/handoff/archive/<date>-*.md`          |
| `AGENTS.md` §"First action"      | Read it first, unprompted; its role is in-flight / needs-owner / branch state    |
| `AGENTS.md` size paragraph       | A long narrative goes in a record, not the hand-off                             |
| restructure §2.5 + `R-0417`      | Target ~150 lines; the decision that cut it 3,396 → ~150                        |

🔑 **Every one of those describes the destination. None describes the trip.** Nothing said what to
do at session close — that the records go in **before** the hand-off is touched, which figures must
be regenerated rather than edited, what to delete, or when to archive. So the procedure was
re-derived from scratch each session, by whoever happened to be closing it.

**The skill is `.claude/skills/handoff/SKILL.md`**, six steps:

1. **Refuse to start if the records are not in.** The hand-off is a view over the store; writing
   the session narrative here *instead of* into records is how the file reached 3,396 lines.
2. **Regenerate every figure, never edit one in place** — open counts, branch position, assertion
   counts, gate numbers. Each of those already carries a "this will rot" warning in the file
   itself, which is what made them the mechanizable part.
3. **Rewrite only the sections that changed**, with a note of what each section may hold.
4. **A deletion pass**, whose test is _would a fresh session act differently without this?_ — not
   _is it true?_ The two sections cut on 2026-08-09 were both true and neither was load-bearing.
5. **Size, and when to archive** — and that archiving is its own change with its own record, not a
   silent step inside a routine close.
6. **Gates, then stop** without committing.

📌 **Deliberately does not restate what the file is for.** It points at "How this file works now"
instead. Two descriptions of one rule is the drift this whole restructure exists to stop, and a
skill that copies the contract would be a second place to update when the contract moves.

📌 **Project-scoped rather than in `~/.claude/skills/`,** because every step names
`work_tracking/` scripts and this repo's gates. It is useless anywhere else, and the repo's other
skills are all general-purpose.

⚠️ **Two adjacent findings, neither fixed here** — they are not this change's job:

- **Six record files disagree with the store about their own status.** `R-0421`, `R-0423`,
  `R-0424`, `R-0425`, `R-0428` and `R-0435` all say `open` in their frontmatter blockquote while
  the store has them `done`. The store is authoritative so nothing is actually wrong, but the
  hand-off tells every session to **read the record rather than its row**, and a reader who does
  that here gets a stale answer. `store.test.js` already pins the H1 against the title; the
  frontmatter status has no such gate.
- **`README.md:13` labels the hand-off `docs/handoff/HANDOFF.md`** while linking to
  `./work_tracking/HANDOFF.md`. The link resolves, so `link-check.js` is silent — it checks
  targets, not link text. A stale label is a different defect from a dead link.
