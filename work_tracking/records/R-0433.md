# R-0433 — Closing the cross-subdomain login friction was rejected — both designs mean owning a bearer credential Firebase does not validate

> **decision · abandoned · rejected** · 2026-07-28 · §9
> Lifted from `docs/planning/pending/tenancy-url-model-decision-20260728.md` §2.3
> (`docs/planning/pending/tenancy-url-model-decision-20260728.md#2.3@b77e5af`).

---

**Under host-based tenancy the friction was: one login per subdomain, per browser.** Firebase's
web SDK persists auth in `localStorage`, which is per-origin and cannot be scoped, shared or
inherited — so each mountain's subdomain is a separate session store. The friction itself was
small, and had already been accepted as won't-fix.

**Closing it was considered and rejected.** There are two ways, and they share the same cost:

1. **A one-time handoff code** passed from one origin to the other.
2. **A parent-domain session cookie** on `.mohocats.org`.

🔑 **Both mean a bearer credential that Firebase does not validate — our code does.** Issuance,
TTL, replay protection and revocation all become ours to design, implement and keep correct.
That is a new security surface, bought for a convenience that had already been priced as low.

⚠️ **This is the sibling of `R-0396`, and the two together are the whole answer to "why not
single sign-on across mountains?"** `R-0396` rejects cross-origin session _propagation_ because
it **multiplies** the sign-out defect — every propagation design mints the second origin its own
refresh token, so more origins hold live sessions and sign-out stays broken. This record rejects
the convenience fix on its own terms, independent of that defect.

📌 **The question stopped being live when tenancy went path-based** (`R-0395`): one origin means
one session store, so there is no friction left to close and no credential to own. The reasoning
is kept because it is the argument to re-run if a future mountain ever opts into its own hostname
under `R-0434` — at which point every cost here returns for that tenant.
