# R-0438 — The "643 of 1,274" grep figure is withdrawn; never-grep-the-store stands on reproducible evidence instead

> **decision · done · adopted** · 2026-08-09
> Raised by the owner, who did not recognise the rule when `R-0425` carried it into `AGENTS.md`
> and asked where it came from.

---

**The rule is kept. Its stated evidence is not.**

`SCHEMA.md`, the restructure doc (§4.3's results table **and** §7's watch-outs) and `lib.js:13`
all said a grep pre-filter "was measured finding **643 of 1,274** matching rows, because JSON
serialization is not canonical." Four files, and it reads like corroboration. It is **one claim
quoted four times**, all four written in the same session on 2026-08-08.

**Why it could not stand.**

- 🔴 **The measurement cannot be reproduced.** No harness, corpus or command was ever committed —
  `git log --diff-filter=A` finds nothing. The commit that settled the storage decision (`efa17ce`)
  narrates four of the ten scenarios in detail and **does not mention the grep one at all**.
- 🔴 **The direction is wrong for the store as built.** Re-tested on the real
  `registry.ndjson`, grep does not halve a result set — it **over-counts**, because the file is
  append-only and grep reads superseded revisions as current. `grep -c admin` returns 38 where the
  answer is 36; the store is 470 rows folding to 437 records.
- 📌 **Its stated cause no longer applies either.** "Serialization is not canonical" was true of
  whatever corpus was tested; `lib.js`'s `FIELDS` array exists precisely so that "a record written
  today and the same record written next year produce byte-identical lines." The writer is
  canonical by construction.

**What replaces it — two failure modes, each demonstrable in one command.**

1. **Grep misses, because values are JSON-escaped.** `R-0004`'s title displays as
   `Every 집사톡 post opened on "Post not found."` and is stored as `\"Post not found.\"`:
   `grep -c '"Post not found."'` returns **0**; the escaped form returns 1; parsing returns 1.
   26 rows currently carry a quote in `title` or `note`.
2. **Grep over-counts, because the file is a log.** Every revision is still there. Only a reader
   that folds to the highest `rev` per `id` answers "how many records match".

Plus the one that needs no measurement: **a raw match cannot say which field it hit.**

✅ **Use `checkout.js --query`**, or the `current_records` view in `registry.db`. Both parse, both
fold to the current revision, both let you name the field.

🔑 **The lesson is about how this repo writes things down, not about grep.** A specific number
carries authority that outlives the measurement behind it, and it gets copied into other files
faster than it can be checked. **A figure whose harness is not committed should not be written
down as a fact** — state the mechanism, which the next reader can re-derive, or commit the
experiment. This is the same failure the whole restructure exists to stop, in the documents
describing the restructure.

📌 **The §4.3 row is marked withdrawn rather than deleted.** It is a record of what was measured
on 2026-08-08, and rewriting history to match what is true today would be the other failure mode.
