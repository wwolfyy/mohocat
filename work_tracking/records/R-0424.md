# R-0424 — Phase 4 — apply a size policy to `docs/handoff/`, so the living document cannot grow back

> **task · open** · 2026-08-09
> Migrated from `work-tracking-migration-plan-20260808.md` — Phase 4, third item
> (`work-tracking-migration-plan-20260808.md#phase-4@44e08fe`).

---

**The archive mechanism already exists** — `docs/handoff/archive/` holds 33 files — and it simply
stopped being applied to the living document. That is how `HANDOFF.md` reached 3,396 lines and
~268 KB, which is the failure the whole restructure was opened to fix.

**Cutting the file once (`R-0417`) does not stop it happening again.** `HANDOFF.md`'s own closing
section now says "keep it short" and "if this file starts growing a narrative again, that
narrative belongs in a record" — but that is an instruction, not a policy, and the same
instruction existed in spirit before.

📌 **What "a policy" means here is open**: a line threshold that triggers an archive, a CI check,
or a rule stated in `CLAUDE.md` at Phase 5. Worth deciding deliberately rather than by default —
a check that fails the build on a long hand-off is enforceable in a way a paragraph is not.

⚠️ Note the tension with the previous entry in this phase: `PROJECT_PLAN.md` is 332 KB
(`R-0423`), and a size policy scoped only to `docs/handoff/` would not have caught it.

## ✅ Done — 2026-08-09

**The policy is a CI gate.** `work_tracking/size-policy.json` holds a budget per document;
`work_tracking/scripts/size-check.js` enforces it; the `work-tracking` CI job runs it as a third
step beside the two that already exist. `node work_tracking/scripts/size-check.js --report` prints
every document and how much room is left.

**Two owner decisions shaped it** (2026-08-09):

1. **Scope is every living document, not just `docs/handoff/`** — which resolves the tension this
   record opened with, in its favour. Governed: `HANDOFF.md`, `PROJECT_PLAN.md`, `SCHEMA.md`, the
   two design docs, and — an addition made while building — the three **stubs**
   (`BACKLOG.md`, `DEBUG_LOG.md`, `FEATURE_MOD_LOG.md`). Exempt: `registry.md` and `registry.db`,
   which are generated and are *supposed* to grow; `archive/**` and `completed/**`, frozen by
   definition; and `records/*.md`, one item each.
2. **It fails the build.** A warning would have been the same shape as the thing that failed.

🔑 **Guarding the stubs is the part that was not in the plan, and it may be the most valuable
part.** `HANDOFF.md` says "do not add entries to `DEBUG_LOG.md` / `FEATURE_MOD_LOG.md` /
`BACKLOG.md`" — a rule with nothing behind it, which is precisely the shape of rule this record
exists to replace. A 60-line budget on a 34-line stub turns "please don't" into "cannot".

🔑 **A budget is a ratchet, not an aspiration.** Each is set just above the file's real size on
2026-08-09, so a document cannot grow without someone **raising the number in a diff**. Raising it
is allowed and expected; doing it by accident is what stops. The alternative — a round number
picked from nowhere — leaves years of silent headroom, which is how a 3,396-line hand-off happens
without anyone deciding to write one.

⚠️ **It measures lines _and_ the longest line, because the two failures this workstream was opened
over are invisible to each other.** `HANDOFF.md` failed on **lines** (3,396). `PROJECT_PLAN.md`
failed on **columns** — a single 4,350-character table cell, with a line count that looked
perfectly healthy at 1,490 (`R-0423`). Either check alone catches one and misses the other.

📌 **The count is characters** — not bytes, not rendered width. `awk` says 399 where this says
385 for the same line, because Korean is three bytes per character in UTF-8 and renders
double-width again. None is more correct than the others; what matters is that a runaway cell is
thousands on any of them, and that the budgets were set with this same function.

**Verified, and the gate is proven to fail** — `work_tracking/tests/size.test.js`, 12 assertions
run through the real script as a child process, asserting on the **exit code** CI actually reads:
over-budget on lines exits 1, over-budget on columns exits 1, a governed file that has vanished
exits 1 rather than being skipped, an empty policy is refused rather than passed, an entry with no
`remedy` is refused, and an unknown flag exits 2. ⚠️ The tests point the script at a scratch policy
through `WORK_TRACKING_SIZE_POLICY` rather than editing the committed one — an interrupted run
would otherwise leave the repo's own gate mangled.

📌 **A failure says what to do.** Every policy entry carries a `remedy`, printed on breach: archive
and cut a fresh hand-off; move prose into records; *this is a stub, the entry belongs in the
registry*. A gate that only says "too big" gets its threshold raised.

➡️ **`R-0425` must carry this into `CLAUDE.md`** — the size policy is a rule an agent has to know
before it starts appending, not after CI tells it.
