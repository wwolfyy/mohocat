# R-0416 — Import a decision only when its reasoning is recorded nowhere else

> **decision · done · adopted** · 2026-08-09
> Migrated from `work_tracking/MIGRATION_JOB.md` — "Decisions made during execution" and the
> files 5–6 session entry (`work_tracking/MIGRATION_JOB.md#D-dedup-rule@44e08fe`).

---

**Owner's rule, 2026-08-09.** A decision found while reading a source document is imported only
if its reasoning exists nowhere else in the store. If an existing record already carries it, the
decision is dropped and the existing record is named.

**It was measured, not felt.** 56 decision-shaped passages survived the read of `HANDOFF.md`.
Each was probed against all 346 records then in the store, and **20 turned out to be already
covered** — mostly because the same person wrote `DEBUG_LOG.md` and the hand-off about the same
event on the same day, and the log entry is the fuller of the two. 36 were imported.

🔑 **The dropped 20 stay visible.** They live in `handoff.js`'s table under `COVERED_BY_EXISTING`,
each naming which record won, so the call is auditable rather than invisible. A de-duplication
you cannot review is indistinguishable from data loss.

**What the rule protects:** a store that answers questions, rather than a second copy of the
documents it replaced. Four of the seven decisions the migration plan listed by name were
themselves already in the store — which is the measurement that produced the rule in the first
place.

📌 The rule applies to this pass too. `R-0408` folds an answered owner question and its matching
decision-table row into one record for exactly this reason.
