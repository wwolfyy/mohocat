# R-0409 — Source files are migrated one at a time, each ticked off before the next begins

**Owner's call, 2026-08-08.** Work the source files one at a time, and record each file's
progress separately: extracted, count verified, origin cut.

**Why:** a 315-row import — 326 as it turned out — will not finish in one session, and a
phase-level tick loses the resume point. "Phase 2 in progress" tells the next session nothing
about which of seven files it is halfway through; "file 4 of 7 done, file 5 not started" tells it
everything.

**A file counted as done only when its migrated content was deleted from the origin in the same
commit that added the rows**, and the count was the gate: extracted had to equal the
hand-verified source count before anything was deleted. That gate earned its keep on
`PROJECT_PLAN.md`, where the plan's own count of 171 was wrong and `--expect` caught it — the
true total was 182.

📌 The decision survives the tracker that carried it. The per-file table is gone, but the same
discipline now lives in the registry as ordered open records: one row per remaining piece of
work, not one row per phase.
