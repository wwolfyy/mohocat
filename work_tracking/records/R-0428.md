**What the move costs, and why it is not just `git mv`:**

- Every inbound link to either file breaks — `AGENTS.md` / `CLAUDE.md`, the stubs in

  archived body already needed fixing for, where 53 links were repointed one level.
- `R-0417` archived the hand-off's body to `docs/handoff/archive/`; whether the archive follows
  the file is a separate call, and worth making explicitly rather than by omission.

📌 **Sequencing suggestion, not a decision:** doing this with `R-0425` means the orientation
rewrite names the final paths once, rather than naming `docs/` paths that move a week later.

## ✅ Done — 2026-08-09, with `R-0425`

`docs/planning/PROJECT_PLAN.md` → `work_tracking/PROJECT_PLAN.md`,
`docs/handoff/HANDOFF.md` → `work_tracking/HANDOFF.md`. **84 links repointed:** 65 inside
`PROJECT_PLAN.md`, 14 inside `HANDOFF.md`, and 5 pointing at them from `README.md`, the two
manuals, and the archived living document.

🔑 **The archive does not follow, and that was already settled — this record's open call had an
answer.** `R-0407` is the owner's decision that relocating superseded artifacts to `docs/archive/`
is a **by-hand** job the migration does not do, and the restructure doc §3 says the same of
`docs/planning/`, `docs/handoff/` and `log/`. So `docs/handoff/` keeps `archive/` and `testing/`,
and `docs/planning/` keeps `BACKLOG.md`, `pending/` and `completed/`. `R-0427` remains deferred on
that same move.

⚠️ **Links were repointed by resolving and re-relativizing, not by rewriting path prefixes.** Each
link was resolved against its file's old directory and re-expressed relative to the new one, so no
path shape had to be anticipated. Two things that only fell out of doing it that way:

- **Ordering matters.** The two files link to each other, so rewriting the first while the second
  is still at its old path leaves that one link behind — the existence check correctly declines to
  point at a file that is not there yet. Every `git mv` now happens before any rewrite. Caught by
  the before/after check, not by reading.
- **Re-relativizing everything churns the repo.** A first pass rewrote 50 links across 17 files,
  but most were `](sibling.md)` → `](./sibling.md)` in `docs/codebase/` — cosmetic noise in files
  the move never touched. Only links whose **target** moved are rewritten now; the real number is
  5.

📌 **Already-broken links are left exactly as they are.** A repo-wide check found **193 broken
relative links before this change**, mostly in `docs/handoff/archive/`, where files were relocated
into `archive/` and never repointed. Re-relativizing a broken path yields a differently broken
path and buries the original, so the rewriter skips any link that does not currently resolve.
That pre-existing rot is filed separately as `R-0437`.

**Verified.** A before/after link check across **1,046 relative links in every tracked `.md`**:
193 broken before, 193 broken after, **0 newly broken**. Plus the three store gates, and
`size-policy.json` repointed at the new paths in the same change — which the policy's own
"a governed document that has vanished is a breach" rule caught when it was momentarily missed.
