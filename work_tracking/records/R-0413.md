# R-0413 — `type` gains `question` — an unanswered owner question is not a task

> **decision · done · adopted** · 2026-08-09
> Migrated from `work_tracking/MIGRATION_JOB.md` — "Decisions made during execution"
> (`work_tracking/MIGRATION_JOB.md#D-type-question@44e08fe`).

---

`BACKLOG.md`'s `Q1` was slated to import as `type: task`. **That file's own heading says open
questions are "not tasks until answered"** — filing one as a task is the category error the
restructure's §2.2 names: a task is work you intended, a question is a decision nobody has made
yet, and putting them in one bucket means "what is open?" mixes work with waiting.

**`question` therefore became the fifth `type`.** A question becomes something else once it is
answered — usually a `decision`, sometimes a `task`. `R-0408` in this same pass is that shape:
the tracker's one owner question, answered, filed as the decision it turned into.

📌 **This was the first schema change made under `R-0410`'s not-frozen policy**, and it cost
nothing: adding an enum value is additive, so every row already in the store still loaded.
