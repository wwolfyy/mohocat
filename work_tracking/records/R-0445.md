# R-0445 — Six record files state a status their row contradicts, and no gate compares the two

> **task · open** · 2026-08-10
> Found on 2026-08-09 while searching for what the repo already said about the hand-off. Recorded
> as its own item on 2026-08-10 under R4 — it had been sitting in `R-0439`'s prose, where nothing
> queries it.

---

**Every record file opens with a frontmatter blockquote naming its type and status.** Six of them
disagree with the store:

| Record   | File says | Store says |
| -------- | --------- | ---------- |
| `R-0421` | `open`    | `done`     |
| `R-0423` | `open`    | `done`     |
| `R-0424` | `open`    | `done`     |
| `R-0425` | `open`    | `done`     |
| `R-0428` | `open`    | `done`     |
| `R-0435` | `open`    | `done`     |

All six are from the 2026-08-09 migration session, closed by a check-in that revised the row and
left the prose file's header alone.

⚠️ **Nothing is actually wrong — and that is the problem.** The row is authoritative, so
`registry.md`, every query and every count are correct. The damage is to a habit the hand-off
insists on: **"read a record, not just its row"**, which it earned by catching the same import
twice on the same day. A reader who follows that instruction here is told the item is open.

🔑 **`store.test.js` already pins the H1 against the title** — `R-0436` could not land until all
139 record files were updated, because that assertion refused it. **The frontmatter status has no
equivalent**, which is why this drifted and the titles could not.

📌 **The fix is two pieces and they should land together:** correct the six headers, and add the
assertion, or it recurs on the next status change. ⚠️ **Check the parse first** — the blockquote is
free prose (`> **task · done** · 2026-08-09 · §7`), not a structured field, and some records carry
a `§`-reference or an `outcome` in the same line. An assertion that cannot read every existing
header would have to be written to skip what it does not understand, which is the kind of gate that
passes by not looking.

📌 **Deliberately not fixed inside `R-0439`**, which was about writing the `/handoff` skill. A
change that repairs unrelated rot is a change whose own diff cannot be read.
