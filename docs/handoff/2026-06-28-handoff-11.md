## 0. Where we are (read first)

This session **fixed the permission system end-to-end and locked down the admin API**. Started
from a reported bug ("no users show in `/admin/members`") and pulled the thread through several
compounding root causes. **Everything is committed and pushed to `dev`; nothing is pending.**

The Firestore **rules were re-deployed by the owner during the session** (3 times, as each layer
was uncovered). The later commits are **app-only** (API routes + client) and ship via the normal
Vercel/`git push` path — no `firebase deploy` needed for those.

> ⚠️ **The headline lesson:** `hasPermission` in `firestore.rules` had **never worked** — it was
> defined _outside_ the `match /databases/{database}/documents` block, so `$(database)` was unbound
> and **every** permission-gated rule silently denied everyone (cats, posts, contacts, users).
> Keep rules helpers **inside** the match block.

### The two new reusable helpers

- **`src/lib/auth/requireApiPermission.ts`** — server-side gate for admin API routes (Admin SDK; mirrors the Firestore rule). Returns `{ ok, uid } | { ok:false, status, error }`.
- **`src/lib/auth/authHeader.ts`** — client helper: `authHeader(user)` → `Authorization: Bearer <idToken>` for calls to gated routes. Used by RolePermissionConfig, RoleManagement, ResourcePermissionConfig, YouTubeAuthPanelNew.
