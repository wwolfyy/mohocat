## 1. What this project is (one paragraph)

Next.js 14 (App Router) site for a non-profit cat community. Map-centric landing
page (계양산 feeding-point map → cat galleries) built on **Leaflet**; content/data
from **Firebase** (Firestore + Storage); deployed on **Vercel**
(`https://mohocat.vercel.app`). Admin is `react-admin` and is **out of scope**.

Read [`docs/design/design.md`](../design/design.md) first — it is the design
source-of-truth (intent + usage; token _values_ live in `tailwind.config.js`).

## 2. What this session did — modal design-system unification

Goal: every **user-facing modal** shares one look/behavior. Theme was established
from the `CatGallery` + `CatInfo` modals, then propagated. All work is committed
and **browser-verified** except where noted in §6.

**The theme — "warm card floating over the map"** (now codified in `design.md` →
`### Modal` and `### Media viewer`):

- Frosted dark backdrop (`bg-black/50 backdrop-blur-sm`) + fade-in; white
  `rounded-xl shadow-xl` card + scale/fade pop-in.
- **Neutral circular ghost close** (top-right) — the old **red square** close
  button is gone everywhere (red is reserved for destructive actions only).
- Restrained brand-yellow accents: avatar hover rings, section-label underlines,
  status pill, brand-tinted action chips.
- Primary action inside a modal = **brand→accent gradient, `text-ink`**;
  secondary = `bg-gray-100`. Destructive confirm (logout) stays red; vendor
  buttons (Kakao `#FEE500`) are never re-themed.
- Deliberately **narrow** sizes so the map shows around the card.

### New shared building blocks (all in `src/components/ui/`)

| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 4. Notable bug fixed (carry this knowledge)

`Modal` renders through a **portal to `document.body`**. Reason: the frosted
header uses `backdrop-blur`, and `backdrop-filter` (like `transform`) makes an
ancestor a **containing block for `position: fixed`** descendants. The
`LogoutModal` is rendered from inside the header (`NavigationBarLogout`), so
without the portal it was **trapped/clipped inside the header band** with no
backdrop. The portal makes every modal immune to this. Keep new modals on the
shared `Modal`; don't hand-roll `fixed inset-0` shells.

## 5. Conventions (unchanged — see prior hand-off §4–6 for full detail)

- **Verify in a real browser**, not compile/lint alone. Dev: `localhost:3000`,
  driven via the Claude-in-Chrome extension (`/chrome`).
- Media (thumbnails / about photos) are **build-fetched from Firebase, not in
  git** → a fresh checkout needs **`npm run fetch:assets`** or markers/photos 404.
- **Single shared Firebase for dev AND prod**; Firestore content is live at
  runtime → admin/console text edits hit production instantly. Only _code_ deploys.
- `npx tsc --noEmit` must stay clean (quick gate). `npm run lint` has only
  **pre-existing** warnings (`<img>` usage on Firebase media — intentional, the
  image optimizer stalls on full-size remote URLs; and a few `exhaustive-deps`).
- Keep Tailwind brand tokens literal in source so the JIT generates them.
- Work in small, browser-verified chunks.
