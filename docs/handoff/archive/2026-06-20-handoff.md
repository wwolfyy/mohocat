## 4. Build / asset pipeline (IMPORTANT operating context)

- **Media (cat thumbnails + about photos) are build-time artifacts, NOT in git.** Fetched from Firebase Storage by `scripts/maintenance/fetch-static-assets.js`. Gitignored (`public/images/thumbnails/*`, `public/images/about-photos/*`).
- **A fresh `next dev` checkout will be missing them** → markers show no avatars, about-page image 404s. Run **`npm run fetch:assets`** once (needs the Firebase key at `config/firebase/mountaincats-61543-*.json`, or `SERVICE_ACCOUNT_KEY` env) to populate `public/images/...`.
- The fetch is **fail-loud**: a configured about photo, or a thumbnail that exists in storage but fails to download, **aborts the build** (`process.exit(1)`); a cat with no thumbnail in storage is a warning. There's a post-fetch on-disk assertion for about photos.
- `vercel-build` runs the fetch (`fetch-static-assets.js && next build`); the full `build` also runs it.
- ⚠️ Out-of-scope observation: the main `build` script also runs `export_all_to_cloud_storage.js` on **every** build (writes TO storage) — questionable; review if touching the build pipeline.

## 5. Data / environments (CRITICAL — easy footgun)

- **Single shared Firebase project for dev AND prod** (bucket `mountaincats-61543…`). There is **no dev/prod data separation**.
- Page **text/content is fetched live from Firestore at runtime** (e.g. about page via `aboutContentService.getAboutContent()`, with static JSON fallback). So **content edits in the admin console go live to production instantly** — no commit/push/deploy. Only **code** changes need a build+deploy. Treat admin edits as production edits.

## 6. How to work here (conventions)

- **Verify in a real browser, not compile/lint alone.** Dev server: `localhost:3000`. Drive it with the Claude-in-Chrome extension (user types `/chrome`). Only mark UI work done against observed behavior.
- **Work in small chunks, one at a time** (user preference / token budget).
- **`npx tsc --noEmit`** must stay clean (the project's quick gate; `npm run lint` also available).
- Keep Tailwind brand-token classes **literal** in source (incl. inside baked marker HTML strings) so the JIT generates them.
- Coding: try/except must log + re-raise (no silent fallback) — see the fail-loud asset pipeline as the example.
