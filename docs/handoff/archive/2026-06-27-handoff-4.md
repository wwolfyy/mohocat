## 4. 🔴 Prominent deferred — bake the data layer (PROJECT_PLAN §7a)

Surfaced this session while discussing the gallery's fetch path. The app reads
Firestore **live from the browser** on key surfaces, gating content on
_hydration → Firebase Web SDK init → cold connection → query_ and shipping the heavy
Firebase SDK to the client. Hotspots: the **landing map cat avatars**
(`LeafletMountainMap` `usePointMarkers` — N parallel `getCatsByPointId` queries
post-hydration) and the **galleries** (`getAllCats()` client-side). The home page
already bakes **points** at build (async Server Component, no `dynamic`/`revalidate`);
the fix extends "bake occasional-change reads" to cat metadata via **SSG + ISR /
on-demand revalidation on admin save**, and evaluates the **Admin SDK** for
server/build reads (`page.tsx` currently uses the client Web SDK server-side). Full
detail + checklist in **PROJECT_PLAN §7a**. The new adoption gallery deliberately
follows the existing live-client pattern for now; it's a candidate to migrate when
§7a is picked up.
