## 5-feat. Inline image/video links

New tokens for any processed text: `[img:설명](url)` → in-app **Lightbox**;
`[video:설명](url)` → in-app **VideoPlayer** (YouTube/Storage auto-detected). Mirrors the
`[catmodal:이름]` pattern.

- `text-processing.ts`: `convertImageLinks`/`convertVideoLinks`, run **before** the generic
  markdown converter (same ordering reason as catmodal).
- Shared hook `hooks/useMediaLinks.tsx` (one delegated click handler + Lightbox/VideoPlayer
  overlays), consumed by **`CatInfo`** and **`CatLinkedText`** so tokens work in both and are
  never inert. Builds minimal `CatImage`/`CatVideo` from the URL.
- Admin `linkHelp` panel (About editor) documents the two tokens.
- **Where they render:** cat modal, 입양홍보 posts, About page. **Not** in 공지사항 /
  급식현황 / 집사톡 (those render `post.message` as plain text — a known gap).
- ✅ Browser-verified the image→Lightbox path (injected link click). Video is the identical
  handler → VideoPlayer.

## 7. Gotchas / notes

- **Link tokens don't render everywhere.** Only cat modal / 입양홍보 posts / About process
  them; 공지사항·급식현황·집사톡 show raw text. Don't tell operators to use tokens there yet.
- **`[catmodal:이름]` takes no parentheses** (the paren form breaks — logged in `DEBUG_LOG`).
- **Overlay stacking is dynamic** (handoff-20): the new `useMediaLinks` Lightbox/VideoPlayer
  reuse the existing components, which already portal to `<body>` + use `useModalLayer`.
- **Empty-album dataset locally** (handoff-20) — cat photo/video _albums_ are empty, so the
  album buttons can't be exercised with data; the inline `[img]`/`[video]` links don't depend
  on that (they take a URL directly).
- **`docs/manuals/`** is the new home for operator + deployment docs; `docs/codebase/` stays
  developer-facing.
