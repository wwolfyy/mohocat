## 3. Mobile hamburger menu closes on route/sign-in (`e64f168`) — DEBUG_LOG

`Navigation` lives in the persistent root layout, so `isMobileMenuOpen` survived navigation.
Result: (a) tapping 로그인/등록 left the dropdown open over the login page; (b) after sign-in the
menu stayed open (the 로그인 link sets `redirect=<current path>`, so pathname may not change).
Fix — one effect: `useEffect(() => setIsMobileMenuOpen(false), [pathname, isAuthenticated])`.
Bug (a) browser-verified at 390px (`<Link>` is client-nav + layout doesn't remount, so the close
is the effect firing).

## 4. Mobile logout modal actually logs out (`e1b571b`) — DEBUG_LOG

Pre-existing (from `c632f76`). The menu's outside-click handler listens on **`pointerdown`** and
closed the menu for any target outside `<header>`. `LogoutModal` portals to `<body>`, so tapping
its confirm button fired `pointerdown` first → the menu (and the modal, its child) unmounted
**before the button's `click`** → `signOut()` never ran. Fix: bail when the `pointerdown` target
is inside a `[role="dialog"]`. Outside-click dismissal browser-verified still intact at 390px;
the logout leg itself is credential/device-owed.

## 5. Mypage inline edit-button layout (`cd3c29d`) — FEATURE_MOD_LOG

닉네임 / 이메일 재인증 / 전화번호 edit rows crammed the `flex-1` input and both buttons into one

change, live confirm device-owed.

## 6. Mobile login/logout menu-pill centering (`3ccd414`) — FEATURE_MOD_LOG

In the hamburger menu the login/logout pills are block-level flex containers, so they filled the
row with content packed left → dead space on the right. Added a `mobile` prop to both
`NavigationBar{Login,Logout}` that applies `w-full justify-center` (matching the 입양홍보 CTA).
Only the two mobile-menu instances pass `mobile`; desktop pills unchanged. Login pill
browser-verified centered at 390px; logged-in logout pill shares the mechanism (device-owed).
