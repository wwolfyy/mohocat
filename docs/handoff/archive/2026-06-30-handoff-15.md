## 2. AdminAuth emergency-bypass removed (commit `0cd9c2c`)

The "🚨 Emergency Bypass" / "Emergency Bypass (Dev Mode)" buttons on AdminAuth's error/loading
screens **never granted access** — they only cleared local error/loading flags, then fell back
through the real `!user || !isAdmin` gate to the login screen. So they were dead + misleading
(the comments claimed "mock admin state"; the code did no such thing). **Removed both**
(the owner's call: delete, not gate-to-dev). Also dropped three unused `useAuth()` bindings
(`isAuthenticated`/`providerData`/`linkedProviders`).

## 3. react-admin subsystem removed (commit `d963d30`)

Investigation showed the entire react-admin stack was **dead code**:

- `src/lib/admin/dataProvider.ts` + `sampleData.ts` — imported by nothing.
- `ImageList` / `ImageEdit` / `VideoList` / `VideoEdit` — rendered by nothing (no `<Admin>` /
  `<Resource>` host context exists anywhere). The **real** `tag-images` / `tag-videos` admin
  UIs are hand-built on the service layer and were never react-admin.

**Deleted** all 6 files and the **8 deps** that existed solely for them — `react-admin`,
`ra-data-fakerest`, `ra-data-firebase-client`, `ra-ui-materialui`, `@mui/material`,
`@mui/icons-material`, `@emotion/react`, `@emotion/styled` (`npm install` pruned **85
packages**). `tsc` + smoke + `next build` all green.

## 4. AdminAuth → `useAuth()` consolidation + create-user cleanup (commit `dc1d748`)

The session's one real refactor — **AdminAuth.tsx −131 lines net**. Folds three §5 items:

- **Two auth listeners → one.** AdminAuth ran its _own_ `onAuthStateChanged` subscription
  **in addition to** the app-wide one in `AuthProvider` (which `useAuth()` already exposes).
  Removed AdminAuth's listener; it now derives `user` + `loading` from `useAuth()`, keeping
  only its **own admin-privilege check** (made cancellation-safe with a proper in-flight flag,
  so a user-switch can't write a stale result).
- **10s init-timeout removed.** It was a vestigial guard for the long-fixed ~48s
  `indexedDBLocalPersistence` hang (now `browserLocalPersistence`; see `src/services/firebase.ts`).
  It could only ever **mis-fire mid-login** via the old effect's `[loading]` dependency. Deleting
  the self-owned listener removed it entirely — no re-scope needed.
- **Render split into mutually-exclusive states:** `loading` (`authLoading || (user &&
isAdminLoading)`) → `login` (`!user`) → `access-denied` (`user && !isAdmin`) → `shell`. The
  old `authError` string-state + `resetAuthState` are gone; the access-denied case is now a
  focused screen (Sign out + Back to main site) instead of the generic "Authentication Error".
  Inline-style look **preserved** (visual work is deferred — no re-skin).
- **Dead `/admin/create-user` removed.** The page **does not exist** (browser-confirmed 404),
  yet `admin/layout.tsx` **bypassed auth** for that path (latent unguarded-route risk) and
  AdminAuth linked to it twice. Removed the bypass + both links.

**Email-login UX:** added a small local `isLoggingIn` flag (button → "Signing in…", disabled)
to replace the feedback the removed local `loading` used to give.
