## 1. S22 map bug — thumbnail pins vanished on pinch-bounce — `4595cbf` ✅ S22-verified by owner

**Full symptom→cause→fix is in `DEBUG_LOG.md` (newest entry) — read that; summary here.**

- **Symptom:** on an S22 (not a Note 9), after a pinch-out the map "snaps back to fit" and the
  individual **cat-thumbnail pins randomly disappear**, while the **number clusters stay**.
- **Root cause:** Leaflet's `TouchZoom._onTouchMove` only hard-clamps a pinch to the zoom limits
  when **`bounceAtZoomLimits` is `false`** — it **defaults to `true`**. So a pinch-out let the
  live gesture zoom travel _below_ `minZoom` (= the fill zoom) mid-pinch; `leaflet.markercluster`
  reacted to that transient sub-fill zoom by **merging** the standalone pins into clusters, and
  the bounce-back's **re-split intermittently failed on the S22** (device-dependent rounding/timing
  in its `_mergeSplitClusters` state machine) → pins stayed merged; clusters (already clusters)
  persisted.
- **Fix:** one line — `bounceAtZoomLimits={false}` on the `MapContainer`. The pinch hard-stops
  **at** fill, so the sub-fill excursion never happens. Device-independent; complements the earlier
  `minZoom → exact fillZoom` clamp (that governs the _committed_ zoom; this governs the _transient_
  gesture). **Owner confirmed it checks out on the S22.**

## 2. Step-back review — is the map over-engineered? (owner-prompted, no code)

The owner asked to sit back and check the accumulated map machinery for convolution before adding
more. Conclusion (recorded here so it isn't re-litigated):

- The **orientation/width split, rotation, drag-gate, remount** pieces were clean and independent
  — not the source of the churn.
- The complexity concentrated in the **cluster ↔ zoom knot** (four settings reconciling _one_
  tension: markercluster wants integer grid levels from `getMinZoom()`, we want a hard stop at a
  fractional fill zoom). `bounceAtZoomLimits={false}` is the _simple_ root fix, not a patch on a
  patch; the `temp-lower-minZoom-by-4-while-building-the-grid` trick in `PointMarkersLayer` is the
  one "clever" line — correct + commented, **the first place to look** if markercluster misbehaves
  on a new device or a new mountain's point layout.
- **Decision: keep clustering** (owner — it'll matter for other mountains). The knot is the price;
  it's stable + documented.

This review directly motivated §3 (portrait-lock lets us _delete_ the orientation half of the knot).

## 3. Portrait-first mobile — `1ea0b5d` (+ cat GIF polish)

**Owner direction:** the information architecture doesn't suit a horizontal phone layout; make the
app portrait-first like a native app (except lightboxes may rotate for media viewing). **Hard web
truth surfaced:** a browser tab **can't truly lock orientation** (only an installed PWA / fullscreen
can), and Tailwind breakpoints are width-based, so a landscape phone (~780px) crosses `md` and gets
desktop styles regardless. The web-equivalent is a **portrait-first presentation + a rotate-notice
where landscape genuinely breaks.** Two paired changes:

### 3a. Nav stays one line in landscape (`Navigation.tsx`)

- Desktop-nav breakpoint moved **`md` (768) → `lg` (1024)**. A landscape phone (~780px, just over
  `md`) previously flipped to the full desktop nav (3 dropdowns + CTA + 집사메뉴 + login) which
  wrapped to two lines; it now keeps the **one-line hamburger**.
- **Accepted tradeoff (owner-approved):** the **768–1023px** band (small tablets, split-screen,
  narrow laptop windows) now gets the hamburger too. Consistent with the mobile-first direction.

### 3b. Map is portrait-only on phones (`MountainViewer.tsx`, new `hooks/useIsPhoneLandscape.ts`)

- A phone held in landscape is **no longer given a sideways/ballooned map**. It gets a scoped
  해요체 notice instead — **지도는 세로 모드에서만 볼 수 있어요. / 기기를 세로로 돌려주세요** — with a
  rolling-cat GIF hero (§3c). Detection: `useIsPhoneLandscape()` = the media query
  `(orientation: landscape) and (max-height: 540px)` (catches phones in landscape, ≤ ~430px tall;
  excludes tablets ≥ ~600px and desktops).
- **Scoped to the map page only** (it's an early-return inside `MountainViewer`). The rest of the
  app stays usable in landscape, and **album/cat lightboxes live on other pages → unaffected**, so
  wide photos/videos still view in landscape (the owner's lightbox-exemption ask is satisfied for
  free — no explicit exemption logic needed).

### 3c. The map's orientation machinery was DELETED (net simplification)

Because the map is now portrait-only on phones, **device and orientation coincide** → a single
`isMobile` flag drives everything. Removed:

- **`hooks/useIsPortrait.ts`** (deleted — was used only by `MountainViewer`).
- The map's separate **`portrait` prop** (`LeafletMountainMap` + `PointMarkersLayer`) — folded into
  `isMobile`, which now drives the rotated-portrait image + coords, container aspect, `Compass`,
  clustering, +/− buttons, and drag-gate.
- The **`key={portrait}` remount-on-rotate** — the key is now the rotation-invariant device class
  (`isMobile ? 'mobile' : 'desktop'`), so no image-swap remount.

This is the exact orientation code the recent S22 map bugs churned through — **−92 lines** net on
the map side.

### 3d. Rolling-cat GIF hero (`a770a57` → `7914680`)

The notice hero went: 🙂 emoji → CSS-`animate-cat-roll` 🐈 emoji (`dab0fea`) → **an owner-supplied
GIF** (`public/images/chubby-cat.gif`). Final state:

- Rendered via **`next/image` with `unoptimized`** — critical: Next's optimizer would otherwise
  flatten a GIF to a single static frame; `unoptimized` keeps it animated (verified the served src

- Final asset is **60×56, ~20 KB** (an earlier drop was 1.4 MB — owner re-exported it pre-sized).
- The interim `animate-cat-roll` utility + keyframes were **removed** (dead once the GIF landed).

## 7. Gotchas / notes

- **`bounceAtZoomLimits` defaults to `true`** in Leaflet — a pinch overshoots the zoom limits and
  bounces back unless you set it false. That transient overshoot is what desynced markercluster on
  the S22. (DEBUG_LOG newest entry.)
- **`leaflet.markercluster` reads `map.getMinZoom()` when it builds its grid** (`layer.addTo`) — the
  temp-lower-minZoom-by-4 trick in `PointMarkersLayer` exists for this. Don't "simplify" it away.
  It's the first suspect if pins mis-cluster on a new device/mountain.
- **A browser tab can't lock orientation** (no PWA manifest here — plain tab). Portrait-first on web
  = a rotate-notice, not `screen.orientation.lock()`. The notice is deliberately **map-scoped**.
- **GIFs + `next/image`:** always pass **`unoptimized`** (or the optimizer flattens the animation).
  A raw `<img>` also works but trips the `no-img-element` lint rule.
- **A GIF can't be paused by `prefers-reduced-motion`** the way the earlier CSS emoji could — an
  accepted caveat for a small decorative hero. Swap to `<video>`/Lottie if that ever matters.
- **`isMobile` (width) vs the old `useIsPortrait` (orientation):** now unified — the map keys
  everything off `isMobile`. A **portrait tablet** (≥768px wide) therefore gets the _landscape_ map
  (minor, rare; not the overlay). Left as-is by design.
- **Verification harness limits:** `resize_window` still lies; the iframe harness stalls on the map
  ≥768px (use a real tab / device for desktop-map + all touch/animation). See handoff-24 §1.
