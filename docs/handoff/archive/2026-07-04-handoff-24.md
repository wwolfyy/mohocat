## 1. Verification tooling — SETTLED (the handoff-23 §6 blocker)

`resize_window` is broken (resizes the OS window chrome but does **not** reflow the page's
content viewport — screenshots stay desktop-width). The working method, **validated and now the
standard for mohocat mobile checks:**

- **An iframe sized to phone width genuinely reflows.** Navigate a tab to `localhost:3000`
  (same-origin so you can script into the frame), inject an `<iframe id="mv-frame">` at e.g.
  390px, and expose `window.__mvSet(width, route)`. Prove it reflows before trusting it: a
  390px frame reports `innerWidth 390` + `matchMedia('(min-width:768px)').matches === false`.
- **Caveat:** the iframe reflows layout/CSS media queries but does **not** emulate touch,
  pinch, orientation change, or device-pixel-ratio. Those stay **device-owed**.
- **Also:** the iframe harness **stalls on the map at wide widths** (dynamic-import loading
  never resolves ≥768px) — a harness quirk, not app code. For desktop/landscape map checks,
  use a **real second tab** instead (its window was ~400px here, so mobile-portrait only —
  `resize_window` couldn't widen it either).
- Recorded as memory `mobile-viewport-harness.md`.

## 3. Map: zoom / orientation / scroll — `6eb1937`, then `1cae86c`, `19a78d4`

Three owner-reported mobile-map bugs (Samsung Galaxy S22), all in the map engine
(`LeafletMountainMap.tsx` / `MountainViewer.tsx` / `Compass.tsx` / new `hooks/useIsPortrait.ts`).
**Full symptom→cause→fix detail is in `DEBUG_LOG.md` (3 newest entries) — read those; summary here.**

1. **Zoom-out grey margins** — `minZoom={-3}` let a pinch zoom out far below fill, exposing the
   grey container bg. → clamp `minZoom` to the fill zoom.
2. **Landscape wastes space** — the portrait-vs-landscape image was chosen by **width < 768**
   (`useIsMobile`), not orientation, so a landscape phone under 768px kept the tall portrait
   image jammed sideways. → new **`useIsPortrait()`** (`matchMedia('(orientation: portrait)')`)
   drives image / coord-rotation / container aspect / compass / remount-key by **orientation**;
   `useIsMobile` (width) still gates clustering / +− buttons / drag.
3. **Can't scroll the page over the map** — Leaflet one-finger `dragging` captured vertical
   swipes (`touch-action: none`). → **owner-chosen model:** on mobile, keep drag **disabled at
   fill** (`touch-action: pan-x pan-y` → page scrolls) and enable it only when zoomed in past
   fill (where there's room to pan). Pinch-zoom + 전체보기 still work.

**Then two follow-ups (both important — the map went through 3 iterations):**

- **`1cae86c`** — the zoom clamp made the **cat-thumbnail pins vanish** (all collapsed into
  clusters). `leaflet.markercluster` derives its cluster grid from `map.getMinZoom()`; a
  minZoom at the exact fill zoom put the default view on the grid's bottom level → total merge.
  Interim fix: `Math.floor(fillZoom)`.
- **`19a78d4`** — the floor was **device-dependent**: on a Note 9 `floor(fillZoom) ≈ fillZoom`
  (hard-stops at fit), but on the **S22** the floor sat ~1 zoom level below fill so the map
  **rested zoomed-out with grey**. Final fix **decouples** the two needs:
  - **Zoom limit** → clamp `minZoom` to the **exact** `fillZoom` (true hard stop at fit, every
    device, no grey).
  - **Pins** → in `PointMarkersLayer`, **temporarily lower `minZoom` (−4) while the cluster grid
    is built** (`layer.addTo`), then restore the exact clamp. The grid keeps a level at the
    display zoom, so the 4 pins + 2 clusters render while the map still can't zoom out past fill.
  - A `zoomend` **snap-back was tried and abandoned** — Leaflet swallows a `setZoom` issued from
    inside a `zoomend` handler (verified empirically).

Verified on a real 410×776 portrait tab (via a temporarily-exposed map handle, since removed):
`setZoom(-2)` holds at fill (no grey); 4 pins + 2 clusters at default; drag disabled at fill
(page scrolls) / enabled when zoomed in (map pans).

## 4. Album nav greyed for public — DIAGNOSED, not code (owner to fix in CMS)

The 사진첩 / 동영상 nav links are greyed for anonymous visitors. **Root cause: data, no
regression.** The live Firestore doc `role_permissions/resource-config` still gates
`photo_album → view-photo` and `video_album → view-video` (`updatedAt: 2026-06-21`). The
planned CMS flip from handoff-23 §4a was **never saved**.

Key clarification the owner asked about — **"방문자(visitor)" ≠ an anonymous browser:**

- `viewer` (displayed 방문자) is a **role assigned to a signed-in user**. Giving it
  `view-photo`/`view-video` only helps logged-in viewers.
- A **not-signed-in browser** is hardcoded to **`permissions = []`** (`usePermissions.ts`:
  `if (!user) setPermissions([])`) — it does **not** inherit any role. So it matches no required
  permission.
- In this system, "public to everyone incl. anonymous" = a resource with an **empty** required
  list. That's why about/동참/공지/FAQ (all `[]`) work for anyone.

**Fix (owner):** `/admin` → **Resource Permissions** → uncheck `view-photo` on 사진첩 and
`view-video` on 동영상 → Save (writes `[]`). The album **pages** are already public (no server
gate); this only un-greys the nav. The admin save path (`ResourcePermissionConfig` → POST) is
correct — no bug. _(Not done yet as of this handoff.)_

## 6. Gotchas / notes (map engine especially)

- **`leaflet.markercluster` reads `map.getMinZoom()` when it builds its grid** (at
  `layer.addTo`). Clamping minZoom to the fill zoom collapses all pins → we temp-lower minZoom
  around the build, then restore. Don't "simplify" that away.
- **Leaflet swallows `setZoom` called from inside a `zoomend` handler** — re-entrancy. Snap-back
  patterns don't work; clamp via `minZoom` instead.
- **`map.fitBounds(bounds)` was a no-op** in the snap-back attempt (0 events) while
  `map.setZoom(fillZoom)` worked — noted in case fitBounds is reached for again.
- **`useIsMobile` (width) vs `useIsPortrait` (orientation) are now distinct** — image/coords/
  compass follow orientation; clustering/+−/drag follow width. Keep them separate.
- **Anonymous browsers have zero permissions** (`usePermissions`: `!user → []`) — the CMS
  "방문자/viewer" role never applies to them. Public = empty required-permission list.
- **`resize_window` lies; the iframe harness stalls on the map ≥768px** — see §1.
- **Album greying is a CMS/data toggle, not code** — see §4.
