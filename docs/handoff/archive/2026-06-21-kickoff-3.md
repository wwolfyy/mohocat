## 1. What MOHOCAT is (one paragraph)

산냥이집냥이 ("MOuntain cat and HOuse CAT") is a Korean-locale, non-profit
awareness platform centered on a **full-bleed Leaflet map of 계양산 (Geyang)**,
where cat-pins (feeding points) open galleries of current/former resident cats.
**Next.js 14** (App Router, TypeScript strict) deployed on **Vercel**; all
data/auth/media run on a **single shared Firebase project** (Firestore + Storage

- Auth). Slow-changing entities (cats, points, feeding-spots) are exported to
  **Google Cloud Storage static JSON** at build / admin-trigger time; real-time
  data goes through Firestore directly. The system is **multi-tenant-_ready_** (one
  `MOUNTAIN_ID`, `config/mountains/mountains.json`) but only one mountain is live.
  A `react-admin`-adjacent CMS under `/admin` manages cats, media, posts,
  announcements, members, and roles.

## 2. Architecture at a glance

- **Service-factory seam.** Components never touch Firebase directly; they call
  `getXxxService()` → interface-typed lazy singletons (~13 services in
  `src/services/`). This is the intended seam for future per-mountain DB
  separation and for mock-based testing — **no mocks exist yet**.
- **Hybrid data loading.** Cats/points/feeding-spots → GCS static JSON (CDN);
  posts/replies/admin ops → live Firestore.
- **Auth.** Firebase Auth + Kakao OIDC + phone/SMS; a single `AuthProvider`
  context; `permission-service` keeps `users/{uid}` in sync on link/unlink.
- **RBAC.** Four roles (`admin`, `butler-ground`, `butler-internet`, `viewer`);
  Firestore-first config with `config/permissions.json` fallback. **UI gating
  only hides UI — `firestore.rules` is the real gate.**
- **Multi-tenant config.** `src/utils/config.ts` is the single gateway
  (`getMountainConfig()` etc.), keyed off `MOUNTAIN_ID`.
- **Deploy.** Vercel is active (`vercel-build` = `next build`); Cloud Run (legacy,
  manual) and a self-hosted Docker home-server path also exist; Firebase Hosting
  workflows are disabled-but-present.

## 3. Design system state

- **`design.md` is the design source-of-truth** (intent + usage). **Token
  _values_ live only in `tailwind.config.js`** (`brand`/`accent`/`ink`) — never
  duplicate hex into components or a second file.
- **Personality:** warm, playful, cat-focused, but **restrained** — brand yellow
  for _actions and markers_; surfaces stay neutral; dark-on-yellow text; rounded
  shapes; **the map is the visual hero**, chrome floats over it.
- **Language & Voice (codified):** all user-facing copy is **Korean, 해요체**,
  with 집사 (caretaker) framing ("내 집사 정보", not "마이페이지"). Vendor names in
  Korean (카카오톡) but vendor colors/logos unchanged (Kakao `#FEE500`). Auth +
  mypage copy is centralized in [`src/constants/strings.ts`](../../src/constants/strings.ts).

## 6. Operating conventions (carry forward)

- **Verify in a real browser**, not compile/lint alone — `localhost:3000` via the
  Chrome extension. Mark UI work done only against observed behavior.
- **Media (thumbnails / about-photos) are build-fetched from Firebase, not in
  git** → a fresh checkout needs `npm run fetch:assets` or markers/photos 404.
- **Single shared Firebase for dev AND prod** — admin/console content edits hit
  production instantly; only _code_ needs build+deploy.
- Keep `npx tsc --noEmit` clean; `npm run lint` has only pre-existing warnings.
- Keep Tailwind brand-token classes literal so the JIT generates them.
- Work in **small, browser-verified chunks**; update `design.md` + the plan/tasks
  docs as you go.
- **Admin (`react-admin`) is out of scope for the design redesign** — but is now
  explicitly in scope for the new **admin cleanup** workstream (see the plan).
