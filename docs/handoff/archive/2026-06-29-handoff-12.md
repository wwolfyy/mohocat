## 3. State & gotchas to know

- **`cat_videos` is mostly Admin-SDK-written.** tag-videos' per-video metadata edit and batch
  update go through **`/api/update-youtube-video` → `/api/refresh-video-metadata`** (Admin SDK,
  bypasses rules). So that collection was **never** broken by `write: if false`; the rule only
  matters for the **client-SDK** paths (`updateVideo` from "Automatic Date Parsing",
  `syncWithYouTube`). Gated anyway for consistency + to cover those paths.
- **Pre-existing, separate issue (not introduced here):** the browser console logs
  `Failed to load permission config from Firestore: Missing or insufficient permissions`
  (`permission-service.ts` `loadConfig`). The **client** reads `role_permissions/role-config`
  directly, but that collection has **no read rule** → default-deny. Enforcement is unaffected
  (the rule's `hasPermission` reads it server-side via `get()`; the admin matrix UI loads it via
  the gated Admin-SDK route). But any **client-side** permission gating that depends on
  `loadConfig` is silently running blind. Worth a follow-up: either add a read rule for
  `role_permissions` or route the client through the Admin-SDK API. **Out of scope this session.**
- **Benign console noise:** Firestore Web SDK `WebChannelConnection RPC 'Write' stream
transport errored … 400` appears on client writes but the write still succeeds (verified in
  Firestore). Don't chase it.
- **Native dialogs block the browser-automation extension.** tag-images/tag-videos save handlers
  use `alert()`/`confirm()`, which freeze the page for the MCP tools — the owner had to dismiss
  them manually during verification. Keep in mind for future browser-driven admin testing.
