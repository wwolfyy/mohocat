## 0. How we got here (context)

A multi-turn discussion about cat-data type/quality issues converged on this. The thread:

- handoff-12 un-blocked admin CMS writes (`cats` etc. now gated on `manage-cat`, not `write:if false`).
- We then looked at two CMS buttons — **🔄 Migrate Neutering Data** / **📅 Migrate Birth Dates**
  (`src/app/admin/cats/page.tsx`) — which convert **legacy string** values (`"TRUE"`, `"2016"`)
  to boolean/number **in place** on the `cats` docs. They exist **only** because the Google
  Sheets → Firestore importer (`scripts/maintenance/data_updater.js`) writes every field as a
  **string** (Sheets API returns strings). See the `cat-data-sheets-pipeline` memory.
- The form editor already writes correct types (boolean/number); only the Sheets path makes strings.
- We found `data_updater.js` does `batch.set(...)` **without `merge`** → a **destructive full
  overwrite** (wipes app-only fields like `adoptable`). Discussed `merge` (fill absent only, but
  still overwrites present columns) and "Firestore-wins / fill-only" (read-modify-write). There is
  **no Firestore→Sheets export** either, so a Sheets workflow inevitably drifts.
- **Conclusion:** rather than perfecting the Sheets round-trip, build a **spreadsheet UI directly
  on Firestore**. Cell-level `updateDoc` is a partial, typed write — which structurally removes the
  overwrite problem, the string/type drift, and the need for the Migrate buttons going forward.

## 1. The feature

Add a **spreadsheet-like grid** to `/admin/cats` where **each cell is individually editable**,
as a **second view alongside the existing card/form editor**, switched via **tabs** (keep both).

Editing `cats` directly in a grid makes Firestore the single source of truth and gives the
"spreadsheet feel" the owner wants — without the Sheets import/export sync problems.

`cats` is small (~32 docs). Fields (`src/types/index.ts`):
`name, alt_name, description, thumbnailUrl, dwelling, prev_dwelling, date_of_birth (number),
dob_certainty, sex, status, character, sickness, parents, offspring, isNeutered (boolean),
note, adoptable (boolean)`.

---

## 2. Decisions locked this session

- **Keep both UIs.** Card/form editor stays; the grid is an **additional tab** in `/admin/cats`.
- **Write path → client SDK for now** (already gated by `manage-cat` in `firestore.rules`).
  **Flag it with the other Admin-SDK-migration items** (handoff-11 §4 #5 / PROJECT_PLAN §7) — the
  eventual target is to move admin writes behind Admin-SDK API routes and restore `write:if false`.
- **Save model → batch "Save all."** Edits accumulate in local state; one explicit Save commits all
  dirty cells (a Firestore `writeBatch` of per-field `update()`s — partial writes, never full-doc set).
- **Revalidation → yes.** After a successful Save, fire `POST /api/revalidate` (reuse the existing
  `triggerCatRevalidate(user)` path used by the form editor) so baked home/adoption pages refresh.
- **Validation → try options.** Typed columns (boolean→checkbox/select, number→numeric, string→text)
  with `isNeutered`/`date_of_birth` treated as **mandatory** (per the standing decision to make them
  required rather than enabling `ignoreUndefinedProperties`). The exact per-cell error UX is **open —
  prototype a couple of approaches** during the spike and pick one.

### Library

Recommended: **`react-datasheet-grid`** (MIT) — purpose-built editable spreadsheet (typed columns,
keyboard nav, copy/paste, virtualization), low effort at this data scale. Alternative if we want to
own every detail: **TanStack Table v8** (MIT, headless — we build the cell editors). Avoid
**Handsontable** (commercial license). **AG Grid Community** (MIT) / **Glide Data Grid** (MIT) are
heavier than needed for 32 rows. _Final pick to be confirmed in the spike._

---

## 3. Why this resolves the open data issues

- **Overwrite problem → gone.** Grid saves are per-field `update()` (partial); `adoptable` and other
  fields never get wiped. The merge-vs-overwrite question becomes moot for in-app editing.
- **Type drift → gone.** Typed column editors always write the right type. The two **Migrate buttons
  become unnecessary going forward** (only a one-time legacy cleanup would still need them).
- **`undefined`-on-write hazard → handled** by mandatory `isNeutered`/`date_of_birth` validation
  (no blank → no `undefined` reaching the write). `ignoreUndefinedProperties` stays **off** by choice.
- **Single source of truth** → no spreadsheet drift, no Sheets export needed.

## 4. Implementation sketch (for the spike)

1. **New tab in `/admin/cats`.** Refactor the page to host two views (Card | Grid) behind a tab
   switch; both read the same `cats` list (`getCatService().getAllCats()`), both gated by `AdminAuth`.
2. **Grid read.** Map `cats` → rows; define a typed column per field (see §1 list).
3. **Editing.** Track dirty cells in local state (e.g. `{ [catId]: Partial<Cat> }`); no write on edit.
4. **Save all.** On click: validate (mandatory + types) → build a Firestore `writeBatch` of
   `update(doc(db,'cats',id), patch)` per dirty row → commit → on success, clear dirty state +
   `await triggerCatRevalidate(user)` + reload.
5. **Auth/enforcement.** Client SDK write; the deployed `cats` rule (`manage-cat`) is the boundary.
6. **Validation options to try:** inline cell highlight + tooltip vs. a summary banner listing
   invalid cells vs. block-save-until-clean. Pick during the spike.

Gates as always: `npx tsc --noEmit` + `npm run test:smoke`; browser-verify a real edit persists
(this repo's convention — don't mark UI done on compile alone).
