## 1. Why Phase 3 was reverted

Phase 3 attempted two sub-chunks:

- **3.1 (was clean):** delete 8 unreferenced admin permission routes + `MIGRATION_EXAMPLE.ts`.
- **3.2 (sprawled):** remove the **static-data export subsystem**. This is where it went
  wrong — it kept pulling in more surface (admin UI tab, an API route, ~5 scripts, 2
  data files, npm scripts, ~5 doc files incl. a big `copilot-instructions.md` rewrite),
  and mid-way it surfaced that the subsystem is **entangled with the kept asset
  pipeline** (`fetch-static-assets.js`). It was being done reactively, not from a plan.

Decision: reset to end of Phase 2 and **re-plan Phase 3 tightly** — isolated dead code
only; treat the static-data subsystem as its own planned unit (or fold into §7a).

its only reference together, the test count drops by one (expected, not a failure).

### 3B — Static-data export subsystem → **DEFER to §7a (do NOT delete piecemeal)**

The subsystem produces output **nothing reads at runtime** (every surface reads
Firestore live: `getAllCats`, `getPointService`, feeding-spots service). It _looks_
deletable, but it's entangled — handle it as a deliberate unit, ideally inside the
§7a "bake the data layer" workstream (it's a half-built baking attempt; §7a should
decide baking holistically rather than us ripping it out now).

**Full component map (so the redo doesn't re-investigate):**

- `scripts/migration/export_all_to_cloud_storage.js` → exports Firestore → Cloud Storage
  `static-data/*.json`. **Imported by** `src/app/api/admin/update-static-data/route.ts`,
  which is **called by** the admin **"Static Data 관리" tab** in
  `src/app/admin/app-management/page.tsx`. Output is unconsumed.
- `scripts/migration/export_{cats,points,feeding_spots}_to_static.js` +
  `update_all_static_data.js` → wired to the `update:*` npm scripts.
  `export_cats_to_static.js` writes `src/lib/cats-static-data.json` (local).
- **⚠️ Entanglement:** `src/lib/cats-static-data.json` is **also written every build by
  the KEPT `scripts/maintenance/fetch-static-assets.js`** (`saveStaticDataJson()`), and
  `scripts/migration/migrate-cats-to-firestore.js` (legacy one-off) **reads** it. So
  it's a **build artifact** (regenerated, not runtime-read), not simply dead data —
  deleting it won't break the build (it regenerates), but removal must also stop the
  write and/or gitignore it. This is the knot that made inline deletion messy.
- `src/lib/feeding-spots-static-data.json` — committed, unconsumed.
- **Docs that reference it** (update when removed): `scripts/README.md`,
  `.github/copilot-instructions.md`, `README.md`, several `docs/codebase/*`
  (`CODEBASE_OVERVIEW`, `deployment-and-build`, `api-routes`, `admin-platform`,
  `media-and-youtube`), `docs/archive/*` (leave archived), and `test_admin_api.js`
  (root — imports `export_all_to_cloud_storage`).

## 3. Key cautions / learnings

- **`tsc` is not run by the pre-commit hook** (only Prettier/ESLint via lint-staged).
  Run `npx tsc --noEmit` yourself. (A prior test commit shipped a tsc error caught only
  later — the smoke test now targets ES5-safe code.)
- **The app is fully live-read from Firestore** — there is **no** static-data /
  Cloud-Storage read path despite docs claiming one. Baking is §7a (not yet built).
- **`cats-static-data.json` = build artifact**, written by `fetch-static-assets.js`.
- **Keep commits small**; verify each with smoke + tsc.
