## 1. Recipe applied (unchanged from handoff-17 §3)

- Legacy `bg-blue-500/600`, `bg-purple-600` **actions** → shared `<Button>` (`primary`
  = brand gradient default; `secondary` = gray; `danger` = red).
- `focus:ring-blue-*` → `focus:ring-brand-300`; selected-card `border-blue-500` →
  `border-brand-500`; active pagination `bg-blue-500 text-white` → `bg-brand text-ink font-bold`.
- **Native checkboxes:** `text-blue-600 … focus:ring-blue-500` → **`accent-brand-500`** (the
  correct branding mechanism for native checkboxes — see handoff-17 §7; `text-*` is inert).
- Tag chips `bg-blue-100 text-blue-800` → `bg-brand-100 text-ink`; info panels
  `bg-blue-50 border-blue-200` → `bg-brand-50 border-brand-200 text-ink`.
- Page titles got the brand heading-underline motif (`h-1 w-12 rounded-full bg-brand`).
- **Kept as intentional:** YouTube-red (`bg-red-600`) on the YouTube Sync button + video-type
  badge; **purple** as the distinct "date-parsing in progress" status accent (must stay
  visually distinct from the brand `selected` state); `danger` red on Delete.

## 2. `adminStrings` conventions (extend, don't fork)

- One area per surface; `const { area: t } = adminStrings;` then `{t.key}`. Functions for
  interpolation (`saved: (n) => …`). Voice **해요체**.
- Verbose multi-line `alert/confirm` bodies live as single string/function values (e.g.
  `tagImages.alerts.autoParseConfirm(n)`), so the component reads `alert(t.alerts.x(…))`.
- `console.log`/`console.error` left **English** (dev-only, per the global error convention).
