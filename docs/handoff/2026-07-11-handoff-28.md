## 4. `/mypage` logout stranded on a spinner (DEBUG_LOG)

**Symptom:** logging out on `/mypage` left the page on its `!user` spinner — no redirect.
**Root cause:** the client `router.replace`/`push` in the auth guard **never committed** the
navigation after the auth context flipped to null (a known-flaky Next.js pattern). _(First
theory — a double-`router.push` race — was wrong; de-racing it didn't help.)_ **Fix:** drive
the redirect off the auth-state guard and use a **full-page** `window.location.replace`,
which always commits. A `wasAuthedRef` picks the destination: **logout → `/` (landing)**
regardless of which button (in-page, withdrawal, or the top-nav `LogoutModal`); a **direct
logged-out visit → `/login`**. `useRouter` removed from the file. **Owner-verified** on the
dev server (both logout buttons → landing; console `ERR_BLOCKED_BY_CLIENT` on logout is the
**ad-blocker** blocking Firestore's Listen channel — benign, documented in the FAQ, not a bug).
